Class
Consumer no MPS, single card
One consumer GPU. The whole game was getting more work out of it without buying anything: collapse the eight competing CUDA contexts down to one, and hand the freed CPU cores the game-playing.
The tricks
S4
Multiprocess self-play actors+3.2x
16 CPU worker processes play search games in parallel instead of one at a time, filling the idle cores on the 24-thread Ryzen.
S5
Shared eval server+4.2x on top
ONE process owns the GPU and batches every actor's neural-net forward into a single call. Kills the context-switch thrash that had a consumer 3080 pegged at 95% while doing almost no useful work.
S8
C++ board-plane builder54x / call
fill_planes writes the 7x9x9 input tensor in one C++ crossing instead of Python array math per position. Plane building fell from 46% of an actor's CPU to under 4%, byte-for-byte identical output.
TF32
Tensor-core training math~2x backward
The RTX 3080 tensor cores run the training step's matmuls at TF32 precision, roughly halving the backward pass with no measurable quality cost.
micro
Python hot-path trims
No torch.distributions in the loop, precomputed mini-board indices, deferred GPU syncs, and load_state_dict instead of deepcopy for opponents — a steady drip of overhead removed from the innermost code.
Is the agent still learning as much?
Faster games only count if the learning survives. The proof is gen-10 — the first generation grown entirely on the new engine. To be crowned it has to beat the current champion (gen-9) on a 300-game panel and not slip against random, win/block, or the gregory ruler. Right now it is climbing — head-to-head around 52-55% against the 55% bar — and gets re-checked every 30 minutes. The moment it promotes clean, the speedups are confirmed to have cost nothing in strength. Watch the Training tab's promotion gates for the call.
